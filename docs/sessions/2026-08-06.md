## Decisions
- **Applied the shared-helper refactor alongside the one-line fix** → the bug existed because
  the modifier check was retyped three times; fixing only the third copy leaves the shape that
  produced it. Behaviour-neutral for the two shortcuts that were already correct.
- **Used `UnityEngine.Debug.LogError` in the new catch, not `Development.LogError`** → the
  project wrapper is `[Conditional("DO_LOGS")]`, so on any platform without that symbol the
  catch block would compile to nothing. Commented in place so it doesn't get "tidied" back.
- **Guarded `_restarting` with `#if !UNITY_EDITOR`** → the editor branch never assigns it, so an
  unconditional field would be read-never-written in editor compilation (CS0649).
- **Committed only the `bundleVersion` hunk of `ProjectSettings.asset`; `DEBUG_MODE` stays
  local and uncommitted** → confirmed with Tiago that the `Standalone: DO_LOGS;DEBUG_MODE`
  define is deliberate, and that blocking the build while it is active is exactly its purpose
  (`BuildValidator.cs:13-18`). It is therefore a **per-developer working-tree toggle**, not a
  repo setting: committing it would fail Standalone builds for every clone and every client
  branch. The committed value stays `Standalone: DO_LOGS`.
- **H17 logged, not fixed in this change** → the same `Core.settings` null-deref pattern exists
  in ~15 other classes (it's H13's cousin). Fixing one file piecemeal while the pattern stands
  everywhere is the worse outcome; it wants one pass with a shared guard.

## Gotchas hit
- **A register entry can be right about the line and wrong about the consequence.** C8's
  entry described corruption written to disk. The line was never reached, because the scene's
  Key is `remoteAssetsPath` and the code said `assetsPath`. Reading source alone cannot tell
  you which `case` labels are live — **the authored Key strings live in the scene**, and
  `grep -n "Key:" CoreSetup.unity` is the check. The same applies to every other `SetData`
  override (`SocketsSettings`, `OSCSettings`, `OneCoreClient.Settings`): each is a string
  contract with the scene that nothing validates. Worth auditing them the same way.
- **My first C8 fix was itself dead code.** I corrected the assignment inside a `case` that
  never matches, and would have committed a "fix" that changed nothing had `code-reviewer`
  not gone to the scene file.
- **A `default:` that logs is only safe once every key is handled.** Adding the unknown-key
  error before adding the two missing cases would have emitted 3 errors on every save-click,
  because `ConfigsPanel.OnSaveButtonClicked` saves all fields at once.
- **Two of my own fixes re-created the hang I was closing.** Adding `true` to
  `GetComponentInChildren` made it match an *inactive* component — `StartCoroutine` on an
  inactive GameObject only logs, so the boot chain would stall at that hop. And creating a
  second manager when one already exists elsewhere (`CoreSystemUI` finds one via
  `FindObjectOfType`) hits the new duplicate branch, whose `Destroy(this)` is **deferred** —
  so `AddComponent` returns a non-null component that dies at end of frame, taking its
  coroutines and the completion event with it. Resolve through `Instance` first.
- **Fixing a leak can create a dangling reference.** `ClearCache` destroying textures is
  correct for memory but blanks any `RawImage` still pointing at one. Safe at boot and
  teardown; a mid-session re-cache needs a consumer-reload notification that doesn't exist yet.
  Noted on H4 rather than invented here.
- **I introduced a silent 10x error while hardening against silent errors.** My first
  `SettingsParse.Float` used a bare `float.TryParse`, which takes `CurrentCulture` **and**
  allows thousands separators — so on an en-US machine an operator typing `5,5` gets **55**,
  silently, where the old `int.Parse` at least threw. Now normalises `,`→`.` and pins
  `InvariantCulture` with `NumberStyles.Float`. Any parse of operator input in this codebase
  should be invariant-culture; the machines are Portuguese and the code is not.
- **I claimed docs were updated when they weren't.** Told the user H18/M22/H14 were logged
  before actually writing them. Write the file, then report it.
- **I fell into C7 while fixing C1.** My first version of the new catch used
  `Development.LogError`, which is `[Conditional("DO_LOGS")]` — the fix for a silent-failure
  codebase would itself have shipped a silent failure on iOS/WebGL. `code-reviewer` caught it.
  Anything inside a `catch` must use `UnityEngine.Debug` directly until C7 is fixed.
- **`Debug` is ambiguous in this file.** `MainController.cs` has both `using System.Diagnostics;`
  and `using UnityEngine;`, so bare `Debug.LogError` won't compile — it must be
  `UnityEngine.Debug.LogError`. Same reason `Development.cs` fully qualifies it everywhere.
- **Platform-guarding a method body can orphan its field.** Moving the assignment behind
  `#if !UNITY_EDITOR` left the field read-but-never-written in editor builds. When you `#if` a
  branch, check the fields it was the only writer of.
