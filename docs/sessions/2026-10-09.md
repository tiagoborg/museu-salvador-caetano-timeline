## The dataset
- 100 events, `id` 0–99, `categoryId = id % 10` (the ten existing categories, in file order), so
  exactly 10 per category. `year = 1920 + round(id × 106 / 99)`: 1920 for id 0, 2026 for id 99. No
  midpoint ties occur, so `Math.Round`'s banker's rounding does not matter.
- Text: PT and EN, three lengths by `id % 3`: short (~30 chars), medium (~100), long (~190),
  prefixed `Exemplo NNN:` / `Sample NNN:`, with the category name inside the medium and long ones.
- Images: `scaling/c<cat>_e<NNN>_i<k>.png`, ten per event, 1000 URLs all distinct.
  - Shape by global index `% 3`: landscape, portrait, square. Long side 512/448/384, short side
    256–384, so the maximum dimension is 512.
  - Pixels: one of five patterns (stripes, checker, rings, dots, waves), seeded per image, hue from
    the category, a category colour bar at the top, the label `C<cat>-E<NNN>-I<k>` in a 3×5 bitmap
    font, and a 10-bit index strip at the bottom. The label and strip alone make every file's bytes
    distinct; `Validate` checks that by SHA-256 rather than trusting it.
  - Opaque (`RGB24`), which matches the crossfade's opaque-only limit recorded on 2026-10-07.
  - Rendered with `Texture2D.SetPixels32` + `EncodeToPNG`, i.e. Unity itself. No new dependency, and
    no Python: there was no shell here to run Pillow, and Unity is what root can drive.
- Every other key of `data` (and `code`) is read from `config/appData.json` and kept, so `allCategories`,
  languages and category names survive, and a re-run reproduces the same bytes.

### Decisions
- **Writes are bounded and idempotent:** each file is written only if its bytes differ, so a second
  run reports `written 0`. The tool writes only inside `assets/scaling/` plus `config/appData.json`,
  and **never deletes**. Strays in its folder are reported by `Validate`, not removed.
- **Chunked generation:** the pipeline's main-thread limit is 5 s, and 1000 encodes will not fit one
  eval. `Generate(first, count)` covers any slice; every call rewrites the two content files (cheap,
  idempotent). The menu item does the whole run in one go.
- **`config/appData.json` is replaced**, by explicit user request; the old 30-event sample survives in
  git. The fixture copy exists so the baseline can install the content in memory without depending on
  which appData copy the boot resolved (see the LocalLow note below).
- **No `AssetDatabase.Refresh` inside `Generate`:** Unity will create 1000 `.meta` files under
  StreamingAssets on its next refresh; root decides when. Those `.meta` files and the PNGs are
  untracked until someone commits them.
- **Galleries are per category**, so with this data every card cycles 100 images and builds 100 dots.
  This is the existing behaviour and is what the baseline should show; bounding it is phase 2.

## Phase 2 — runtime scaling (code complete, not compiled by the worker)
Root's direction: an App-only cache owned by the Timeline screen, no `EnigmaVirtual` change, and full
pooling or virtualization only if the rebuild cost is still material after the bounded indicator.

### Changed
- `App/Timeline/TimelineTextureCache.cs` (new). It is a plain class, not a MonoBehaviour: the production
  constructor takes the screen as its coroutine host, and an internal constructor injects a loader for
  the checks.
  - **API:** `Request(path, Priority.Visible|Prefetch, Action<Lease>) → Ticket`, then
    `Ticket.Cancel()`, `Lease.Texture` and `Lease.Dispose()`, and `Dispose()` on the cache.
  - **Stats:** `ReadyBytes`, `PinnedBytes`, `HighWaterBytes`, `BudgetBytes`, `Active`, `Queued`,
    `MaxActiveSeen`, `LoadsStarted`, `Coalesced`, `Evictions`, `PrefetchDropped`, `Failures` and
    `OverBudgetEvents`.
  - **Rules:**
    - At most 2 loads run at once, and an aborted load keeps its slot until it ends.
    - Requests for the same file are coalesced on the normalized full path, and a visible request
      promotes a queued prefetch.
    - A queued or in-flight load is abandoned only when its last subscriber leaves.
    - Leases pin. Eviction takes unpinned textures first, least recently used first, then those pinned
      only by prefetch.
    - The budget is **soft** for visible textures: an over-budget visible set is kept and logged once
      per crossing. A prefetch is never started while the cache is at or over budget.
  - Remote URLs are refused, as before. Downloading stays a separate later phase.
  - The load timeout is a fixed 30 s, because `WebRequestExtensions.SetFileTransferTimeout` is `internal`
    to the framework.
- `App/Timeline/TimelineCard.cs`:
  - **Signature:** `Create(parent, style, metrics, cache, x, y, wide, imageOnTop)`. Its only callers
    are `Rebuild` and `SelfCheck`, and no editor script names the card.
  - **Visibility:** `SetVisible(bool)`, `Release()` and `IsVisible` are new, and visibility is
    independent of `enabled`. Leaving view keeps the slide index for re-entry.
  - **Leases:** one per layer, released only after that layer is cleared, plus one prefetch lease
    that is never displayed. Advancing makes the visible request **before** letting the prefetch go,
    so the request joins the prefetch's load or finds its texture still cached.
  - **Slide timer:** it now also waits for a load in flight, so the current image stays until its
    successor is on screen.
  - **Indicator:** bounded. 2–5 images get one dot each (`maxIndicatorDots`), more get a
    `current / total` counter (`counterFontSize`). `OnDestroy` releases everything.
- `App/Timeline/TimelineLayout.cs`: `IndicatorDots` and `IndicatorCounter`.
- `App/Screenview/TimelineScreenview.cs`:
  - **New Inspector fields:** `textureBudgetMiB`, with a range of 128–256 and a default of 256, and
    `visibilityMargin`, default 480.
  - **Cache lifetime:** the cache is created in `BuildChrome`. `OnDestroy` releases the cards before
    disposing it.
  - **Rebuild:** releases and deactivates the old cards before its deferred `Destroy`, and records
    each new card's span.
  - **Visibility:** `LateUpdate` → `UpdateVisibility` decides from those spans and the scroll offset,
    with no allocation, and also deactivates out-of-view shells.
  - **Hide:** releases every card.
- `App/Timeline/TimelineScalingBaseline.cs`: `Snapshot` now reports `cardsTotal` (every shell, inactive
  included), `cardsActive`, `cardsVisible`, `counters` and every timeline-cache stat.
  - **Rename warning for comparisons:** the framework-cache keys are renamed
    `frameworkCacheEntries` / `frameworkCacheRuntimeMiB`. The phase 1 `cards=`, `cacheEntries=` and
    `cacheRuntimeMiB=` correspond to `cardsActive=`, `frameworkCacheEntries=` and
    `frameworkCacheRuntimeMiB=`.
- Self-checks: `TimelineTextureCache.SelfCheck()` is new. `TimelineCard.SelfCheck()` is adapted to
  leases and visibility, and three indicator checks were added to `TimelineLayoutSelfCheck`.
- Docs: `overview.md` (client section: visibility, lifecycle, indicator, textures, content) and
  `reviews.md` (five cache findings and one card finding, all Resolved; the old performance
  projection updated in place).
- Not touched: root's `TimelineMediaDownloadCheck.cs` and `Tools/serve_timeline_media.py`, the user's
  Montserrat asset, every framework file, `VERSION.txt` and the scenes.

### Decisions
- **Cards stay as 100 shells, not pooled.** The 10,000 dots and the eager loading of all 100 cards
  were the measured costs. Pool or virtualize only if `ToggleFilter` stays material after this.
- **Visibility from layout spans**, not `GetWorldCorners`: the spans are known at layout time, and the
  only per-frame input is `content.anchoredPosition.x` and the viewport width.
- **Out-of-view shells deactivated.** The canvas then skips their graphics. The cost is TMP
  regenerating on re-entry, which the scroll benchmark will show.
- **A plain class plus a host** rather than a component, so the checks run outside Play mode with a
  synchronous or manual loader.
- **`quiet` flag** for the checks only, so provoked failures do not fill the console.

## Follow-up — size reconcile (code complete, not compiled by the worker)
- **`TimelineTextureCache.ReconcileBytes()`:** returns how many sizes changed. It re-measures each
  ready entry, counting a destroyed texture as 0, recomputes `ReadyBytes`, raises `HighWaterBytes`,

- **Screen:** `TimelineScreenview.LateUpdate` calls it once per unscaled second while cards are
  shown.
- **Self-check:** a synthetic growth case was added, with the fixed 100-unit measure kept. A pinned
  texture grows from 1 to 2 units: the unpinned one is evicted and the pin kept. It grows to 4 units:
  the excess is kept, reported once, and `HighWaterBytes == 4` units. A pinned texture destroyed
  behind the cache reconciles to 0 bytes. The cache check count rises from 36 to 41.
