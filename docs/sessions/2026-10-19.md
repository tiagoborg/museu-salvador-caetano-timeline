# Session log — 2026-10-19

## Focus
Client report: timeline cards show images that belong to other events (Fundador 1937 has none in the
live appData but shows one).

## Changed
- `TimelineLayout.cs`: `BuildGalleries` (per category) and `StartSlide` deleted; `Gallery(item)` returns
  the event's own non-empty, deduplicated image urls.
- `TimelineScreenview.Rebuild`: each slot gets `TimelineLayout.Gallery(item)`.
- `TimelineCard.Bind`: opens on `initialSlide`, else slide 0 (`BindGallery` already clamps).
- `TimelineLayoutSelfCheck`: gallery cases rewritten for per-event galleries (d with no images must be
  empty even though a, b, e in its category have images).

## Decisions
- **Per-event, not per-category** → the client's call: a card must never show another event's photo.
  Origin was a design decision, not a load/cache bug: galleries were shared per category and an
  image-less event opened on slide 0, i.e. the category's first image (1926's certificate).
- **An image-less card keeps its slot geometry** → the photo area is already transparent with nothing
  enabled when the gallery is empty, so no layout change was needed. Collapsing the area would change
  row geometry and card pooling (`Wide`/`ImageOnTop` kinds); not requested.
