## Decisions
- **Docs split three ways** → `overview.md` = how it works (durable), `known-issues.md` =
  what's broken (churns as things get fixed), session logs = the trail. Keeps the architecture
  doc from turning into a bug list.
- **Stable issue IDs (C/H/M/L + number)** → so commits and future logs can reference a defect
  without restating it, and status can move in one place.
- **`VERSION.txt` at repo root as source of truth** → `bundleVersion` lives in binary
  `ProjectSettings.asset` and can't be diffed; a text file can.
- **`AppVersionSync.cs` placed in `Assets/Editor/`, not `Assets/_Script/Editor/`** → that
  folder doesn't exist in this project; editor tooling already lives in `Assets/Editor/`.
  Noted in `CLAUDE.md` so the deviation is discoverable.
- **`doc-reviewer` adapted to C#/Unity rather than kept generic** → replaced the JSDoc/docstring
  framing with XML doc `<param>` checks, and added Unity checks that are actually verifiable:
  config keys against the settings DTOs, prefab/scene contents via script GUID, platform claims
  against `#if` guards + `ProjectSettings.asset`, packages against `manifest.json`, `[MenuItem]`
  paths, serialization claims (`{ get; set; }` is invisible to `JsonUtility`). Also added
  line-number-citation drift, because `known-issues.md` cites ~60 `file:line` locations that
  will go stale as fixes land.
- **Review agents seeded from real findings, not generic checklists** → each one's domain
  section is derived from defects actually present here, so they detect this codebase's failure
  modes rather than textbook ones. `performance-reviewer` requires a magnitude estimate before a
  finding ships (frequency × cost), `security-reviewer` uses a physical/filesystem-access threat
  model rather than a web one, and `silent-failure-hunter` reports **dormant** findings
  separately — real defects on paths the shipped config disables (C2/H3/H4 all hide behind
  `isActive: false`), which is the category that surfaces when a project flips a flag.
- **Fix C4 (paths) before M20 (asmdef split)** → the path change touches most files the split
  would move between assemblies; doing it after means resolving the same conflicts twice.
- **`code-reviewer` agent at user level (`~/.claude/agents/`), single copy** → wanted in all
  projects, and a project-level duplicate would shadow the global one and drift. Trade-off
  accepted: it does **not** travel with a git branch, so teammates need their own copy (or a
  future project-level copy, which then becomes the one to maintain).
- **Language-specific checks made conditional in that agent** → the supplied prompt was
  JS/TS-flavoured; going global meant it would flag JS idioms in C# files. Restructured into
  "apply the block that matches the repo": C#/Unity (from this review's findings), embedded
  (ESP32/Arduino), JS/TS. General sections are verbatim. Frontmatter uses the documented
  `tools: Read, Grep, Glob, Bash` comma form rather than a YAML list.
- **No DI container** → `Core.settings`/`Core.main` are established across the team's projects;
  converting the singletons to properly-lifecycled statics (H1) captures most of the value for
  a fraction of the migration cost.

## Gotchas hit
- **`docs/sessions/_template.md` references `multiplayer-conversion.md` §2/§10** — carried over
  from another project. Those sections don't exist here; the equivalent targets are
  `docs/architecture/overview.md` (decisions/current state) and `known-issues.md` (gotchas).
  Worth editing the template.
- **Prefab inspection changed a finding's severity.** GUID-mapping `Core.prefab` showed it
  contains `Core`, `MainController`, `CoreSystemUI`, `NotifyController`, `ImageLoaderThread`,
  `AppInfo`, `Factory`, `DesignScaler`, `ConfigsPanel`, `Preloader` — but **no**
  `AppDataController` or `TextureCacheManager`. So H2 (`SetupXxx` early-return skipping
  `Init()`) is **dormant**, while H3 is **live in every build**: the create path is the only
  path and it ends with `GetComponent<>()` on the wrong object, so
  `Core.main.TextureCacheManager` is always null. Reading source alone had these backwards.
  Check the prefab before ranking anything in `MainController.Init()`.
- **The template's default config hides the worst defects.** `AssetDownload.isActive: false`
  and `TextureCache.isActive: false` mean C2 (file deletion), H3 and H4 (texture leaks) never
  execute out of the box. Any project that switches those on inherits all three at once.
- **The uncommitted `FormatNumbers` change is a real fix with a new risk.** The old
  `string.Format("{0:N0}", value, "pt-PT")` silently ignored its third argument and used the
  current culture; the new form actually applies pt-PT — but hardcodes the locale in a *base*
  project and throws `CultureNotFoundException` under invariant-globalization builds (M5).
- **The `GetTranslation`→`GetLocalized` migration changes null-semantics** (`string.Empty` →
  `null`) and is only half-applied — `TextureCacheLoader.cs:122-138` still calls the obsolete
  method. Finish it in one pass or the behaviour depends on the call site (M6).
